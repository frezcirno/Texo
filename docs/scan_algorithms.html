block 内部：warp shuffle + shared memory，几次同步就能扫完一个 tile，互相不用通信。
跨 block：block 2 的每个结果都要加上 block 0 + block 1 的总和，但 block 之间没有同步手段。

关键差别：第一遍要不要写 output

Scan-then-Propagate

① 读 input，写局部结果 读 N + 写 N

② 扫描 block 总和 很小，递归

③ 读回 output，加偏移再写 读 N + 写 N

共 4N

Reduce-then-Scan

① 读 input，只算各段总和 读 N

② 每段求前面各段之和 很小，读 L2

③ 再读 input，带 carry 扫描后写 读 N + 写 N

共 3N

两者都要把数据过两遍。区别在于：Scan-then-Propagate 第一遍就把还不完整的结果写进显存，第二遍再读回来改； Reduce-then-Scan 第一遍只留下每段一个数，第二遍重新读 input，算出的就是最终结果。
省下的正好是"中间结果写出去再读回来"的一个 N。
代价：第一遍的求和是按线程交错累加的，元素的合并顺序被打乱，所以 ⊕ 还要满足交换律。 加、乘、max、min 都满足；浮点加法的结果会和顺序扫描有舍入级别的差异。

总结

  • 两种算法的共同点：block 内都只扫描一个 tile，跨 block 都要靠"前面所有 block 的总和"。
  • Scan-then-Propagate 先写出不完整的结果再回头修正：实现简单，只需结合律，但读写 4N，还要递归和多次启动。
  • Reduce-then-Scan 第一遍只求总和，第二遍重新读 input 直接写最终结果：读写 3N，固定 grid、不递归、无动态分配；代价是要求交换律、静态缓冲区不能并发。
  • 实测：大 N 快约 1.3 倍（≈ 4N / 3N），小 N 快 2 倍左右。
  • 下一步：单遍 decoupled look-back（cub 的做法）只读写 2N，正好是剩下的 803 / 543 ≈ 1.48 倍差距。
