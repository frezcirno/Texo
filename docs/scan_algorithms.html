Decoupled Look-back 的实现要点

动态 tile 编号

block 开头对全局计数器 atomicAdd 领号：编号更小的 tile 一定已经在运行，回看等待不会死锁。最后领号的 block 把计数器清零。
换成依赖调度顺序的 blockIdx.x 只快约 5%，所以保留。

状态和值打包成 64 位

≤ 4 字节的 T：状态字和值放进同一个 64 位字，一次读写同时拿到，不需要 __threadfence()。更大的 T 才走"写值 → fence → 写状态"。
N = 1 亿：约 1700 → 约 1050 µs。

epoch 免清零

状态字高位记录调用序号，上一次调用留下的状态对不上序号，自动视为"未发布"。状态缓冲区按需增长、跨调用复用，不用每次 memset。

warp 并行回看

warp 0 的 32 个 lane 各看一个前驱：最靠后的 P 之前的全部丢掉，其余按 lane 顺序归约，所以只需要结合律。全是 A 就再往前看 32 个。

代价：tile 之间要互相等待前驱发布状态。对照实验里跳过回看（结果是错的，只用来计时），N = 1e7 从约 80 降到 52 µs，比 cub 还快：剩下的差距都在前缀传递链上。

关键差别：数据要过几遍显存

Scan-then-Propagate

① 读 input，写局部结果 读 N + 写 N

② 扫描 block 总和 很小，递归

③ 读回 output，加偏移再写 读 N + 写 N

共 4N

Reduce-then-Scan

① 读 input，只算各段总和 读 N

② 每段求前面各段之和 很小，读 L2

③ 再读 input，带 carry 扫描后写 读 N + 写 N

共 3N

Decoupled Look-back

① 读 input，扫描 tile，发布总和 读 N

② 回看前驱 tile 的状态得到 carry 很小，读 L2

③ 加上 carry 后写 写 N

共 2N

Scan-then-Propagate 第一遍就把不完整的结果写进显存，第二遍读回来改； Reduce-then-Scan 第一遍只留下每段一个数，第二遍重新读 input，直接算出最终结果，省掉一个 N。
Decoupled Look-back 把两遍合成一遍：tile 读进来后一直留在片上，拿到 carry 再写出，又省掉一个 N。 代价是 tile 之间要等前驱发布状态。
Reduce-then-Scan 第一遍按线程交错累加，合并顺序被打乱，所以 ⊕ 还要满足交换律；另外两种只需结合律。

总结

  • 三种算法在 block 内都只扫描一个 tile，区别在于"前面所有 block 的总和"怎么得到。
  • Scan-then-Propagate：先写出不完整的结果再回头修正。实现简单、只需结合律，但读写 4N，还要递归和多次启动。
  • Reduce-then-Scan：第一遍只求总和，第二遍重读 input 直接写最终结果。读写 3N、固定 grid、不递归；要求交换律，静态缓冲区不能并发。
  • Decoupled Look-back：单遍 2N、1 次启动，靠发布 tile 状态 + 回看传递前缀；只需结合律，状态缓冲区不能并发。
  • 实测：小 N 时 DLB 最快，比 cub 还快；N = 1 亿时三者为 1255 / 964 / 911 µs，cub 651 µs。DLB 读写最少却只比 RTS 快 6%，瓶颈在回看链。
  • 下一步：用硬件计数器（ncu）定位回看链上的等待时间，这台机器上 ncu 暂无读取计数器的权限。
