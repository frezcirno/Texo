三种注意力头的组织方式

为什么要省 K/V：推理时的 KV cache LLaMA-3 8B：32 层，32 个 Q 头，d = 128，bf16

每个 token 的 KV cache = 2 (K 和 V) × 层数 × Hkv × d × 2 B

解码阶段每生成一个 token 都要把整个 KV cache 从显存读一遍，带宽受限 → KV 越小，生成越快，同一张卡能放的 batch / 上下文也越多。

MQA 最省但效果会掉；GQA 的质量接近 MHA，速度接近 MQA（Ainslie et al., 2023）。

Q 头 → KV 头 Hq = 8, Hkv = 2, group = 4

kv_head = q_head / group

朴素做法的代价 性能用例：Hq = 32, Hkv = 8, S = 1024, d = 128, fp32

① 先展开再算：K.repeat_interleave(group)，把 K/V 复制成 32 个头

K、V 各从 4 MB 变成 16 MB：多写 32 MB 再读 32 MB，GQA 省下的显存在算子里又花回去了

② 原版 gqa.cu：一个 block 算 1 个 query（grid = Hq × S = 32768 个 block）

每个 block 都把它那个 KV 头的 K、V 完整读一遍（2 × 512 KB）

同一份 K/V 被 group × S = 4096 个 block 各读一次。主要压在 L2 上，但依然是 13.9 ms。
目标：一次读进来的 K/V 块，尽量多的 query 一起用。

关键观察：同组的 Q 行在内存里是连续的 示意 S = 100, Br = 64

Q、O 的形状是 [Hq, S, d]，按行展开：

拼起来的好处：S 小时不浪费 group = 4, Br = 64

按头切块（每个头单独补齐到 64 行）

同组拼成 M = group·S 行再切

Grid：(M / Br, Hkv) = (64, 8) blockIdx.x 变化最快

blockIdx.x →（每格 64 行 query）   纵轴：blockIdx.y = kv_head

对应 gqa.cu

// host：每个 KV 头一行 block，M = group·S 行 query
int group = num_q_heads / num_kv_heads;
int M = group * S;
dim3 grid((M + BR - 1) / BR, num_kv_heads);

// device：只用 kv_head 定位，不需要算 q_head
const int kv_head = blockIdx.y;
const int row0 = blockIdx.x * BR;              // 可能跨越两个 Q 头
const float *q_base = Q + size_t(kv_head) * M * d;   // 同组 Q 头连续
float       *o_base = O + size_t(kv_head) * M * d;
const float *k_base = K + size_t(kv_head) * S * d;   // 整个 block 共用
const float *v_base = V + size_t(kv_head) * S * d;

// 之后就是普通的 FlashAttention：BR 行 query × 逐块扫描 K/V
for (key0 = 0; key0 < S; key0 += BC) { ... }    // 见 flash_attention.html

每个 K/V 块读进 shared memory 后被 64 行 query 复用， K/V 的读取量从 32 GB 降到 512 MB；同一 KV 头的 block 同时在跑，这 1 MB K/V 基本都命中 L2。

误差 ~1e-6（题目容差 1e-4）。

总结

  • GQA：group 个 Q 头共用一组 K/V，KV cache 和解码带宽缩小 group 倍，质量接近 MHA
  • 映射是连续分组 kv = h / group（repeat_interleave），不是 h % Hkv
  • 不要展开 K/V；[Hq, S, d] 布局下同组 Q 行连续，直接当成 M = group·S 行的单头 attention
  • block 可以跨 Q 头，S 小时块更满；同一 KV 头的 block 相邻发射，K/V 留在 L2
  • block 内部就是 FlashAttention：分块 + online softmax

参考：Ainslie et al., “GQA: Training Generalized Multi-Query Transformer Models from Multi-Head Checkpoints”, 2023； Shazeer, “Fast Transformer Decoding: One Write-Head is All You Need” (MQA), 2019
