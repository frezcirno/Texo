Softmax 与数值稳定

yi = exi / Σj exj

直接算会溢出：float32 最大约 3.4×1038，而 e89 ≈ 4.5×1038 → inf，结果变成 inf / inf = NaN

分子分母同乘 e−m，取 m = maxj xj：

yi = exi − m / Σj exj − m

每一项 ex−m ∈ (0, 1]，分母 ≥ 1，永不溢出。

代价：必须先知道 m，才能开始求分母 d = Σ exj − m。

朴素做法：遍历三遍 对应 softmax_3kernel.cu

显存流量：读 3N + 写 2N = 5N，外加 3 次 kernel launch

Pass 1 和 Pass 2 读的是同一份输入。能不能把它们合成一遍？

核心想法：边读边维护 (m, d)

读到第 i 个元素时，只记两个数：

mi = max(x1, …, xi)
di = Σj≤i exj − mi

新元素 xi 到来时，之前的和是以 mi−1 为基准算的，换成新基准只需乘一个修正因子：

exj − mi = exj − mi−1 · emi−1 − mi

于是得到递推：

mi = max(mi−1, xi)     di = di−1 · emi−1 − mi + exi − mi

初值 m0 = −∞，d0 = 0。最大值没变时修正因子 = 1；变大时旧的和整体缩小。

映射到 GPU：两遍完成

① 线程内

grid-stride 循环读 float4，用递推在寄存器里维护 (m, d)

→

② warp / block

__shfl_down_sync 做 ⊕，
再经 shared memory 合并各 warp

→

③ 跨 block

每个 block 写 partial (m, d)，
最后一个完成的 block 合并成全局 (M, D)

→

④ 输出

y = ex − M · (1/D)
再读一遍输入，写一遍输出

Pass 2：输出  读 N 写 N

代码骨架

struct MD { float m, d; };

// ⊕：合并两段
__device__ MD combine(MD a, MD b) {
  float m = fmaxf(a.m, b.m);
  // 两边都是 −∞（空线程）时 (−∞)−(−∞) = NaN，必须特判
  if (m == -INFINITY) return {m, 0.f};
  return {m, a.d * __expf(a.m - m) + b.d * __expf(b.m - m)};
}

// Pass 1：每个线程单遍扫描
MD s = {-INFINITY, 0.f};
for (int i = tid; i < N; i += stride) {
  float x = input[i], m = fmaxf(s.m, x);
  s.d = s.d * __expf(s.m - m) + __expf(x - m);   // 递推
  s.m = m;
}
s = block_reduce(s, combine);  // warp shuffle + shared memory，再跨 block 合并

// Pass 2
output[i] = __expf(input[i] - M) * inv_D;

坑：combine 里两边 m 都是 −∞ 时会得到 NaN；线程循环里 s.m 初值是 −∞，但 x 有限，e−∞ = 0 没问题。

总结

  • 递推 di = di−1·emi−1−mi + exi−mi：最大值变了就给旧的和乘一个修正因子
  • (m, d) 的 ⊕ 满足结合律 → 线程、warp、block、grid 各层都用同一个合并函数
  • 三遍 → 两遍：显存流量 5N → 3N，数值稳定性不变
  • 同样的思路推广到 FlashAttention：除了 (m, d)，再维护一个输出累加器 O，最大值更新时一起乘修正因子，于是不必存下整个 N×N 的注意力矩阵
