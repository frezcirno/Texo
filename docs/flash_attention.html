从 online softmax 到 online attention

对某一行 query：分数 sj = q·kj / √d，输出

o = Σj esj − m vj  /  Σj esj − m

分子也是 “以 m 为基准的指数加权和”，和分母一样，换基准时只要乘修正因子。 所以在 (m, ℓ) 之外再维护一个未归一化的输出累加器 õ：

m′ = max(m, maxj∈tile sj)    α = em − m′
pj = esj − m′    ℓ′ = ℓ · α + Σj pj    õ′ = õ · α + Σj pj vj

一次处理一整块 key（tile），全部扫完后 o = õ / ℓ。 初值 m = −∞，ℓ = 0，õ = 0。每块的 p 用完即弃，不需要保存。

外层按 Q 块切给不同 thread block，彼此独立；内层每个 block 自己扫完所有 K/V 块（FlashAttention-2 的循环顺序）。

每个线程：S 块里 4 行 × 4 列，O 里 4 行 × 16 列，全在寄存器。 同一行的 8 个线程是 warp 里相邻的 lane → 行最大值、行和用 __shfl_xor_sync，不经过 shared memory。

K 和 V 分时复用同一块 → 56 KB，T4 的 64 KB 也放得下。Q 预乘 log2e/√d，之后全用 exp2f。

代码骨架 每个线程的视角

float m[4] = {-INF}, l[4] = {0}, acc[4][D/8] = {0};   // 4 行的状态
for (key0 = 0; key0 < S; key0 += BC) {
  load_K_tile(); __syncthreads();
  s[4][4] = Q_tile · K_tileT;                        // 寄存器分块
  tile_max = shfl_max(row_max(s));                  // 8 个 lane 归约
  m_new = fmaxf(m, tile_max);  alpha = exp2f(m - m_new);
  p = exp2f(s - m_new);
  l = l * alpha + rowsum(p);                        // 线程内部分和，最后再归约
  store P to smem; __syncthreads();
  load_V_tile(); __syncthreads();
  acc = acc * alpha + P · V_tile;                   // 同一个 alpha
  __syncthreads();
}
out = acc / shfl_sum(l);                            // 最后统一归一化

Flash 分块

9.7× 加速：1.24 → 12.0 TFLOPS（约 60% fp32 峰值）

原版每个 block 只算 1 个 query，却要把整份 K/V 读一遍， softmax 还由单线程串行。分块后每个 K/V 块被 64 行 query 复用，softmax 在寄存器里用 shuffle 完成。

误差 ~1e-6（题目容差 1e-4），所以不用 TF32 tensor core。

总结

  • online softmax 的修正因子 α = em − m′ 同样作用在输出累加器上：õ ← õ·α + P·V
  • 按 key 分块扫描，S、P 只在片上存在一块 → 显存里不再有 N×N 矩阵
  • 一个 Q 块 × 所有 K/V 块 = 一个 thread block；GQA 下把同组的 Q 头拼在一起，K/V 复用更多
  • 最后统一除以 ℓ，计算结果是精确的，不是近似
